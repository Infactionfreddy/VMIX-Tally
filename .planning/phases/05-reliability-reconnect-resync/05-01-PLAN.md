## Phase Goal

**As a** production operator, **I want** the bridge to reconnect to vMix automatically after a network drop, **so that** tally recovers without manual intervention mid-show.

<objective>
Replace the node-vmix ConnectionTCP transport in VmixConnector with a raw node:net Socket
that implements a self-managed exponential backoff reconnect loop. The public event interface
('tally', 'rosterUpdated') is preserved unchanged — TallyOrchestrator sees no difference.

Purpose: node-vmix's reconnect interval is a hardcoded protected field; replacing it with
node:net gives full control over retry timing, jitter, and re-subscribe sequencing (D-04).
Remove node-vmix from package.json, which also removes the axios transitive dependency.

Output: Updated VmixConnector.ts with raw socket + backoff loop; extended
VmixConnector.test.ts with VMIX-04 reconnect behavior tests; node-vmix removed from
package.json.
</objective>

Backoff formula (D-03 — same on both connectors):
  const base = Math.min(1000 * Math.pow(2, this.attempt), 30_000);
  return base * (0.75 + Math.random() * 0.5);
  // attempt=0 → 1000ms, attempt=1 → 2000, attempt=2 → 4000, attempt=5 → 30000 (capped)
  // For tests: vi.spyOn(Math, 'random').mockReturnValue(0.5) → pure base delay

Critical invariants (05-RESEARCH.md):
1. 'error' ALWAYS fires before 'close' on socket errors — call scheduleReconnect() from
   'close' ONLY. In 'error': call sock.destroy() + log. Never call scheduleReconnect() from 'error'.
2. Create fresh createConnection() on every reconnect — never reuse a closed socket.
3. Clear lineBuffer = '' in 'connect' handler to discard stale bytes from prior session.
4. Reset this.attempt = 0 in 'connect' handler on successful connect.
5. destroyed flag prevents timer from firing after explicit destroy().
