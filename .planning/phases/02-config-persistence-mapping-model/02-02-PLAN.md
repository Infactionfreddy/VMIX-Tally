<objective>
Build the persist↔load vertical slice on top of the Plan 02-01 schema contract:
`src/config/configStore.ts` — a `ConfigStore` class wrapping lowdb's `Low`+`JSONFile`
adapter, with the config file path as a constructor argument (default `config.json` at
cwd, configurable for packaging — RESEARCH Open Q1). It loads the document on init and
exposes a programmatic CRUD surface for connection settings (CFG-01) and the input
mapping (CFG-02). Every mutation runs `schema.safeParse` BEFORE writing; on failure the
whole save is rejected atomically (on-disk file untouched) and a `ConfigValidationError`
is returned/thrown (D-10).

Purpose: CFG-01/CFG-02 — settings and mapping survive a server restart, anchored on the
stable vMix Key (D-01) so a vMix reorder never re-points a camera. This is the slice that
proves the schema contract round-trips to disk and back.
Output: `src/config/configStore.ts` + `src/config/configStore.test.ts`.

Scope boundary: this plan does NOT implement the D-11 missing-file-defaults, D-12
corrupt-file-quarantine, or SC4 crash-simulation behaviors beyond what round-trip/reject
require — those defensive-boot cases are out of scope for this slice. (The store should
still construct cleanly on a missing file via lowdb's `null`→defaults, but the loud-log /
quarantine path is not built here.)
</objective>

```typescript
export const schema: z.ZodType;                       // top-level { version?, settings: { vmix, atem }, mapping }
export type PersistedConfig;                           // z.infer<typeof schema>
export type PersistedMappingEntry;                     // { vmixKey, vmixNumber?, vmixTitle?, atemSource, cameraId }
export interface ConfigValidationError {               // D-10 structured, field-level error for Phase 6 UI
  kind: "config-validation";
  issues: Array<{ path: (string | number)[]; message: string; code: string }>;
  tree: ReturnType<typeof z.treeifyError>;
}
export function toConfigValidationError(err: z.ZodError): ConfigValidationError;
```

DEFAULTS shape for first-boot (RESEARCH Pattern 1):
`{ settings: { vmix: null, atem: null }, mapping: [] }` — settings connections are
nullable (unset on first boot, D-11); mapping starts empty (D-08 partial allowed).

lowdb v7 call shapes (RESEARCH Standard Stack + Pattern 1/2):
`import { Low } from "lowdb"; import { JSONFile } from "lowdb/node";`
`const db = new Low<PersistedConfig>(new JSONFile(path), structuredClone(DEFAULTS));`
`await db.read();` (null on missing → db.data stays DEFAULTS) then `await db.write();`.
Use the `safeParse → db.data = parsed.data → db.write()` primitive (Pattern 2),
NOT `db.update()` (mutates db.data before validation — RESEARCH Open Q2).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hand-edited config / future UI payload → ConfigStore.save | Untrusted candidate document crosses into persisted state; gated by `schema.safeParse` before any write. |
| ConfigStore → local filesystem (`config.json`) | The single disk-touching write path; atomicity provided by lowdb→steno temp+rename. |
| config file path (constructor arg) → `node:fs` | Path is code-controlled (default `config.json` / injected for packaging), not derived from external runtime input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | save(candidate) injects an invariant violation (dup cameraId/vmixKey/atemSource, atemSource≤0, empty cameraId) | mitigate | `schema.safeParse` runs FIRST in every mutation; on failure `db.data` is never assigned and `db.write()` is never called — invalid input is rejected, never persisted (D-10, ASVS V5) |
| T-02-05 | Tampering | torn write corrupts config.json on crash mid-save | mitigate | `db.write()` routes through steno temp-file + `fs.rename` (atomic for readers); the store never truncates-in-place — old valid file survives an interrupted write (SC4) |
| T-02-06 | Denial of Service | unbounded mapping array bloats the document | mitigate | schema `.max(8)` entry cap (D-09, enforced upstream in 02-01) bounds document size at the save gate |
| T-02-07 | Tampering | config path traversal via the constructor arg | accept | path is code-controlled (default `config.json` at cwd / injected for packaging), not from external untrusted input; LAN single-operator tool, no remote path source (ASVS V12) |
| T-02-SC | Tampering | npm installs (lowdb, zod, steno) | accept | installed + slopcheck-clean in 02-01 Task 1 (RESEARCH §Package Legitimacy Audit, all [OK], no postinstall, project-locked D-04); this plan only imports — no new install, no blocking checkpoint required |
</threat_model>
