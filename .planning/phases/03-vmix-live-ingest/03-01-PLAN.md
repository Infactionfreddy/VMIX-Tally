<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vMix HTTP API → parseRosterXml | XML string from vMix port 8088; treated as untrusted bytes |
| vMix TCP push → parseTallyString | Digit string from vMix port 8099; treated as untrusted bytes |
| Disk config → buildRuntimeMapping | PersistedMappingEntry[] from lowdb JSON file; already validated by zod schema |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | parseTallyString — non-0/1/2 chars | mitigate | Coerce unknown chars to 0 (off); never throw. Covered by unit test "X → [0]". |
| T-03-02 | Tampering | parseTallyString — extremely long string (vMix max: 1000 inputs per docs) | accept | Resolver only iterates mapping entries (≤8); extra tally positions are accessed but never stored. No allocation risk at 1000 chars. |
| T-03-03 | Tampering | parseRosterXml — malformed XML or XML injection | mitigate | Regex extracts only key/number attributes; does not evaluate XML entities; no exec path; returns empty Map on parse failure. |
| T-03-04 | Denial of Service | parseRosterXml — pathologically large XML response | accept | fetchRoster has 5s AbortSignal.timeout; response body read inline; no streaming buffer accumulation beyond normal fetch. Low risk on LAN. |
| T-03-05 | Denial of Service | fetchRoster — hung HTTP request | mitigate | AbortSignal.timeout(5000) applied to every fetch call; catch block returns empty Map immediately. |
| T-03-06 | Tampering | buildRuntimeMapping — persisted config with manipulated vmixKey | accept | vmixKey is a lookup key against the live vMix roster; a manipulated key simply misses the roster.get() and is silently dropped (D-04). No lateral elevation. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | node-vmix and pino flagged [ASSUMED] in RESEARCH.md; a blocking human checkpoint is placed before npm install in Plan 02. |
</threat_model>
