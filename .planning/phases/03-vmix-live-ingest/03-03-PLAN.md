## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VmixConnector 'tally' event → tallyOrchestrator | rawTally: number[] — already sanitized by parseTallyString; orchestrator trusts this array |
| ConfigStore → tallyOrchestrator | PersistedMappingEntry[] — already validated by zod schema on write; trusted |
| tallyOrchestrator → resolve() | MappingEntry[] — produced by buildRuntimeMapping from trusted inputs; pure function, no I/O |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering | tallyOrchestrator — rawTally from VmixConnector (already sanitized) | accept | parseTallyString already coerces to 0/1/2; resolve() has its own coerceTally guard. Double-guarded by design. |
| T-03-13 | Tampering | tallyOrchestrator — configStore returns stale/invalid mapping | accept | ConfigStore only writes after zod validation (Phase 2, D-10 reject-on-violation); stale mapping is safe — worst case a camera gets wrong tally until config is updated. |
| T-03-14 | Availability | tallyOrchestrator — handleTally throws unexpectedly | mitigate | Wrap the handleTally body in try/catch; log error and return without crashing the process. The EventEmitter's default 'error' behavior would throw and crash — wrap to prevent. |
| T-03-15 | Information Disclosure | pino structured logs — rawTally and ResolverOutput logged to stdout | accept | LAN-only production tool; stdout logs are for the operator. No PII or secrets in tally data. Operator can redirect logs as needed. |
| T-03-16 | Denial of Service | tallyOrchestrator — high-frequency tally events (rapid vMix switching) | accept | Each handleTally is synchronous (no await in the hot path if configStore.read() is sync); resolve() is a pure function with O(n) where n≤8. Sub-millisecond per call. No throttling needed. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | node-vmix and pino already installed in Plan 02 (post human checkpoint). No new installs in Plan 03. |
