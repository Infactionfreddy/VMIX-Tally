     tools/atem-simulator/test/codec.test.js. The resolver's {program, preview}
     output MUST match this so Phase 4 wires the connector with no contract churn. -->

From tools/atem-simulator: program/preview are each a single ATEM source id
(u16 number) for mixEffect 0 — NOT a per-input array, NOT a camera id.
atem-connection's ProgramInputUpdateCommand exposes:
  cmd.mixEffect === 0
  cmd.properties.source === <number>   // a single source id

The simulator's SwitcherState ALWAYS holds a concrete programInput/previewInput
(defaults to 1) — it has NO "none" concept. The resolver contract MUST add an
explicit "none" (ARCHITECTURE.md resolver sketch uses undefined for absent
program/preview). Do NOT copy the simulator's "always a number" assumption.

The per-camera map is INTENTIONALLY NARROWER than the simulator's two-boolean
bitfield: a single off|program|preview enum per camera (program wins collisions,
D-12). The contended sidecar carries what that collapse discards.
</interfaces>
