<objective>
Implement the keystone: the pure desired-state resolver that takes vMix
live/preview tally + the vMix→ATEM/camera mapping + the manual override layer and
returns exactly one ResolverOutput — the {program, preview} ATEM bus state, the
per-camera off|program|preview map, and the contended/dropped sidecar — fully
implementing the locked precedence chain and exhaustively tested.

Precedence chain (each tier arbitrated by lowest ATEM input #):
  override-program → live-program → preview → off

Purpose: This is the safety-critical spine of a live-production tally bridge. A
wrong red tally on-air is a real failure. The resolver is the part most likely to
harbor logic bugs (multi-program arbitration, override merge, program-wins,
defensive coercion). It must be a total function that never throws (D-13) and
must never mutate live state so clearing an override instantly reveals live (SC2).

Output: src/core/resolver.ts exporting a pure resolve() function, plus
src/core/resolver.test.ts with one explicit test per precedence tier and per edge
case (D-04..D-13) including dedicated SC2 (live-never-mutated) and program-wins tests.
</objective>

- CameraTallyState = "off" | "program" | "preview"
- CameraId = string
- AtemSource = number   ("none" is represented as null)
- DesiredAtemBusState = { program: AtemSource | null; preview: AtemSource | null }   // mixEffect 0
- CameraTallyMap = Record<CameraId, CameraTallyState>
- ContendedReason = "lost-bus" | "unmapped"
- ContendedInput = { vmixInput, reason, atemSource? }
- ResolverOutput = { cameras: CameraTallyMap; bus: DesiredAtemBusState; contended: ContendedInput[] }

<!-- Resolver INPUT shapes (this plan defines them in resolver.ts and re-exports;
     keep them aligned with the eventual Phase 2 mapping + Phase 6 override + Phase 3 tally). -->
- vMix tally: an array where index = vMix input position, value = 0 (off) | 1 (program) | 2 (preview).
  Per PITFALLS Pitfall 2 this is 1000-padded and positional; the resolver treats it as a plain
  number[] of per-input states and does NOT assume "exactly one program" (D-04/Pitfall 3).
- mapping: the vMix-input → { atemSource: number; cameraId: CameraId } relation. Model as an array
  or record keyed by vMix input number. The mapping carries vMix↔ATEM↔camera (D-02, three-way chain).
- overrides: a per-camera sticky layer; each entry forces a CameraId to "program" | "preview" | "off".
  Model so multiple may be active at once (D-09). Live is NEVER written into; overrides are a
  separate argument applied last (ARCHITECTURE Pattern 3 / Anti-Pattern 4).
</interfaces>

  <behavior>
    - resolve(tally, mapping, overrides) returns a ResolverOutput; it is a pure function with no I/O imports and no argument mutation.
    - Live-program arbitration: among vMix inputs whose tally value is 1 (program) AND that are mapped, the mapped ATEM source with the lowest number wins bus.program; all other live-program inputs' cameras are "off" and listed in contended with reason "lost-bus" (D-04, D-05, D-06).
    - Preview: among inputs whose tally value is 2 and that are mapped, the lowest-numbered mapped ATEM source becomes bus.preview; its camera is "preview" unless that same camera is the program winner (then program wins, D-12).
    - Program-wins collision (D-12): if a camera resolves to both program and preview, its CameraTallyState is "program".
    - Override force-off (D-07): an override forcing a camera to "off" sets that camera "off" in the map and removes it from program/preview consideration for the bus.
    - Override force-program beats live (D-08): a camera forced to "program" takes bus.program over any live-program input, even a lower-numbered live one.
    - Multiple forced-program overrides (D-09): among cameras forced to "program", the one whose mapped ATEM source is lowest wins bus.program; others forced-program are "program" in the per-camera map only if physically the bus winner — losers go to contended "lost-bus" (consistent with D-05 physical truth).
    - Override force-preview (D-07): a camera forced "preview" contributes to bus.preview arbitration (lowest ATEM # among preview candidates, live or forced), and is "preview" in the map unless it is also the program winner.
    - Live never mutated (SC2): resolve does not modify the tally/mapping/overrides arguments; calling resolve with overrides then again with empty overrides on the same inputs yields the pure-live result with no residue.
    - Nothing live (D-11): empty, all-zero, undefined, or null tally with no active override yields bus {program:null, preview:null} and every mapped camera "off".
    - Unmapped live input (D-10): a vMix input with tally 1 or 2 but no mapping entry is ignored for the bus and added to contended with reason "unmapped".
    - Total function (D-13): malformed inputs — undefined/null tally, non-array tally, out-of-range or non-integer values, empty mapping, malformed override entries, out-of-range ATEM source ids — never throw; they are coerced/skipped and the result degrades to a safe all-off ResolverOutput. No unbounded loops or allocation on adversarial input (e.g. an oversized tally array is bounded by the mapping, not iterated to 1000+ blindly for output).
  </behavior>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
