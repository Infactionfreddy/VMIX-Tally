**OverrideControls.svelte** — replace stub with full implementation (D-08).

Props: `{ cameraId: string; currentOverride: 'program' | 'preview' | null }`

Implement the toggle trio `[Aus] [PROG] [PREV]`:
- Three buttons, always visible
- Active button: `currentOverride === null` → Aus active; `=== 'program'` → PROG active;
  `=== 'preview'` → PREV active
- Active button style: background `var(--tally-override)` (#ea580c, orange) for PROG/PREV;
  `var(--tally-off)` (#374151) for Aus
- Clicking active button: `handleToggle(target)` sends null (clears override, D-08)
- Clicking inactive button: sends that state
- No optimistic state update — WS broadcast from server drives the state change
  (RESEARCH.md Pattern 8 anti-pattern: do NOT set bridgeState.overrides locally)

Error handling: local `$state` errorMsg; display inline if fetch fails.
Error copy: 'Override konnte nicht gesetzt werden.' (UI-SPEC Copywriting Contract)

Disabled state: all three buttons disabled when `!bridgeState.wsConnected`
  (UI-SPEC §Override Toggle Behavior: "disabled state only when WS is disconnected")

```typescript
async function setOverride(cameraId: string, state: 'program' | 'preview' | null) {
  try {
    await fetch(`/overrides/${cameraId}`, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ state }),
    });
    // No local state update — WS broadcast drives the change
  } catch {
    errorMsg = 'Override konnte nicht gesetzt werden.';
  }
}

function handleToggle(target: 'program' | 'preview' | null) {
  const next = currentOverride === target ? null : target;
  void setOverride(cameraId, next);
}
```

Button minimum height: 36px (UI-SPEC spacing — finger-friendly).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → REST API | Override state, mapping entries, and settings flow from UI form fields through fetch() to Fastify endpoints |
| REST API → ConfigStore | All writes are Zod-validated before reaching ConfigStore |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-A | Tampering | OverrideControls PUT /overrides | mitigate | Server-side Zod validation on override state (Plan 02); frontend sends only valid enum values; 400 returned for invalid; CSRF hook blocks cross-origin requests |
| T-06-04-B | Tampering | MappingEditor PUT /config/mapping | mitigate | Full-document safeParse via existing schema (Plan 02); duplicate vmixKey/atemSource/cameraId rejected by superRefine; max 8 entries enforced |
| T-06-04-C | Tampering | ConnectionSettings PUT /config/settings | mitigate | Zod schema validates host (non-empty string) and port (1–65535 int); invalid values return 400 with ConfigValidationError |
| T-06-04-D | XSS | MappingRow rendering vmixTitle from roster | mitigate | Svelte template auto-escapes; roster titles come from operator vMix config (trusted LAN source); no `{@html}` used |
| T-06-04-E | Tampering | TestControls POST /test/:cameraId | mitigate | Server Zod validates action enum; ephemeral — no ConfigStore write; 503 if ATEM not connected |
| T-06-SC | Tampering | npm packages | accept | No new packages in this plan; all packages verified in Plan 01/RESEARCH.md |
</threat_model>
