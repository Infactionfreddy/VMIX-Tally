# Phase 6 — UI Design Contract

> Visual and interaction contract for Phase 6: Web UI — Status then Control.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled scoped Svelte styles |
| Preset | not applicable |
| Component library | none — Svelte 5 native components only |
| Icon library | none — inline SVG icons only (avoids build dependency, safe for LAN deploy) |
| Font | system-ui stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif` |

**Rationale (from CONTEXT.md Claude's Discretion):** shadcn is React-specific and not
applicable to a Svelte 5 project. No component library is warranted for a single-page
tool with five UI surfaces. Scoped Svelte `<style>` blocks per component keep styles
co-located and eliminate class collisions.

## Layout

### Single-Page Structure

One HTML page. Vertical sections in reading order:

1. **Header bar** — app title + global connection badge strip (vMix | ATEM)
2. **Disconnect banner** — full-width, loud, conditionally rendered (see Color)
3. **Override warning banner** — conditionally rendered when any override is active
4. **Tally grid** — up to 8 camera cards, primary viewport content
5. **Mapping editor section** — collapsible panel below the grid
6. **Connection settings section** — collapsible panel below mapping

No sidebar, no tabs, no routing. One URL, one scroll. The tally grid must be visible
without scrolling on a 1080p display at 100% zoom (standard production monitor size).

### Camera Card Layout

Each card in the tally grid contains (top to bottom):

1. Camera name (heading size, truncated at 1 line)
2. Tally state badge (large, dominant — see Color)
3. Override toggle trio: `[Aus]` `[PROG]` `[PREV]` (label size, horizontal)
4. Test buttons: `[Test: PROG]` `[Test: PREV]` `[Fertig]` (label size, horizontal)

Cards arrange in a CSS grid: `repeat(auto-fill, minmax(180px, 1fr))`, max 8 columns.
Minimum card width 180px ensures tally badge is legible at arm's length.

### Collapsible Panels

Mapping editor and connection settings are wrapped in `<details>/<summary>` elements
(native HTML, zero JS). Summary line shows section name + a one-line status hint
(e.g. "3 Eingänge konfiguriert" or "vMix: 192.168.1.10:8099").

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | CSS Variable | Usage |
|-------|-------|--------------|-------|
| xs | 4px | `--sp-xs` | Icon gaps, badge inner padding |
| sm | 8px | `--sp-sm` | Button padding vertical, label gaps |
| md | 16px | `--sp-md` | Card inner padding, form field spacing |
| lg | 24px | `--sp-lg` | Section padding, card gap in grid |
| xl | 32px | `--sp-xl` | Header height, section top margin |
| 2xl | 48px | `--sp-2xl` | Major section breaks |
| 3xl | 64px | `--sp-3xl` | Page-level top/bottom padding |

Exceptions:

- Camera tally badge minimum height: 48px (touch/readability target at distance)
- Override toggle button minimum height: 36px (finger-friendly on touchscreen if used)
- Disconnect banner: 8px top + bottom padding, full viewport width (no side inset)

## Typography

| Role | Size | Weight | Line Height | CSS Variable |
|------|------|--------|-------------|--------------|
| Body | 14px | 400 | 1.5 | `--text-body` |
| Label | 12px | 600 | 1.2 | `--text-label` |
| Heading | 18px | 600 | 1.2 | `--text-heading` |
| Display | 28px | 700 | 1.0 | `--text-display` |

**Role assignments:**

- **Body (14/400/1.5):** Form field values, mapping table rows, status copy in banners
- **Label (12/600/1.2):** Button text, column headers, badge text inside tally state, section summary hints
- **Heading (18/600/1.2):** Camera name on card, section `<summary>` text, connection settings section title
- **Display (28/700/1.0):** The tally state text inside the camera card badge (`LIVE`, `PREV`, `—`)

Uppercase transform applied to display role only (`text-transform: uppercase`).
All other roles: sentence case.

## Color

Dark surface theme. Rationale: broadcast control surfaces run in dim studio environments;
dark backgrounds reduce glare and make the red/green tally states maximally distinct.

| Role | Hex | CSS Variable | Usage |
|------|-----|--------------|-------|
| Dominant (60%) | `#111827` | `--color-surface` | Page background, card background |
| Secondary (30%) | `#1f2937` | `--color-surface-raised` | Header bar, collapsible panel background, input fields |
| Accent (10%) | `#3b82f6` | `--color-accent` | See accent reserved list below |
| Destructive | `#ef4444` | `--color-destructive` | Clear-override destructive confirm only |

**Accent `#3b82f6` reserved exclusively for:**
- Currently focused form input border
- "Einstellungen speichern" (Save settings) primary button background
- "Mapping speichern" (Save mapping) primary button background

Accent is NOT used on tally states, connection badges, override buttons, or test buttons.

### Semantic Tally Colors

These are NOT in the 60/30/10 split — they are domain-semantic, used only for tally state indication:

| State | Background | Text | CSS Variable |
|-------|-----------|------|--------------|
| program (LIVE) | `#dc2626` | `#ffffff` | `--tally-program` |
| preview | `#16a34a` | `#ffffff` | `--tally-preview` |
| off | `#374151` | `#9ca3af` | `--tally-off` |
| override active | `#ea580c` | `#ffffff` | `--tally-override` |

**Tally override visual treatment:** When a camera has an active override, the card
receives an orange (`#ea580c`) left border (4px solid) AND the active override button
in the toggle trio uses `--tally-override` as its background. The base tally badge
still shows the resolved tally state (red/green/off), not orange — orange signals
the card is under manual control, not what the resolved state is.

### Connection Status Colors

| Status | Color | Usage |
|--------|-------|-------|
| connected | `#16a34a` | Status dot + badge background |
| connecting | `#ca8a04` | Status dot + badge background |
| disconnected | `#dc2626` | Status dot + badge background + disconnect banner |

### Disconnect Banner

When either `connections.vmix` or `connections.atem` equals `"disconnected"`, a full-width
banner renders directly below the header bar with:
- Background: `#dc2626` (same as tally program red — unmistakable)
- Text color: `#ffffff`
- Text: `vMix getrennt — Tally-Daten möglicherweise veraltet` or `ATEM getrennt — Kein Tally-Ausgang`
- Height: auto, 8px vertical padding, 16px horizontal padding
- Position: static in document flow (not fixed/sticky — scroll past if needed)

### Override Warning Banner

When any override is active on page load or at any time:
- Background: `#ea580c` (override orange)
- Text: `X Kamera(s) mit aktivem manuellen Override`
- Dismiss button: `×` on right edge, which hides the banner for the session only
  (overrides remain active; banner can re-appear if overrides change)

## Interaction States

### WebSocket Connection

The browser WebSocket to the Fastify server has its own lifecycle separate from vMix/ATEM:

| WS State | UI behavior |
|----------|------------|
| Connecting (initial) | Tally grid shows skeleton cards (grey, no tally state) |
| Connected | Normal operation, grid populates from snapshot |
| Disconnected / error | Full-page overlay: `Verbindung zur Bridge unterbrochen — Seite neu laden` with reload button |

The WS disconnect overlay is the only full-page takeover in the UI. It renders above
all content (z-index highest) and provides only a reload action.

### Tally State Transitions

Tally state changes arrive as a full snapshot over WebSocket. Svelte's reactive `$state`
updates the store; each CameraCard re-renders its TallyBadge. No animation on tally
changes — instant state flip. Rationale: latency perception in a live production is
worse with a transition (animated state looks "old" until complete).

### Override Toggle Behavior

- `[Aus]` active state: no override, button background `--tally-off`
- `[PROG]` active state: override = program, button background `--tally-override` (orange)
- `[PREV]` active state: override = preview, button background `--tally-override` (orange)
- Clicking the currently active button clears the override (sends `null` to PUT endpoint)
- All three buttons are always visible; disabled state only when WS is disconnected

### Test Button Behavior

- `[Test: PROG]` and `[Test: PREV]` are always visible; `[Fertig]` only visible during
  an active test session for that camera
- Clicking Test: PROG issues `POST /test/:cameraId { action: "program" }`; the card enters
  a test-mode visual: dashed border, `[Fertig]` button appears
- `[Fertig]` issues `POST /test/:cameraId { action: "clear" }` and exits test mode
- Only one camera can be in test mode at a time; opening a new test auto-clears the previous

### Mapping Editor Behavior

- On `<details>` open: `GET /vmix/roster` fires once
- If roster returns inputs: vmixKey selector is a `<select>` populated with `{number}: {title}`
- If roster returns empty: vmixKey is a free-text `<input>` with placeholder `vMix GUID eingeben`
- vmixAtemInput field: numeric `<input type="number" min="1" max="8">`
- "Mapping speichern" button is disabled until any row has been changed (dirty-track per session)
- Save sends `PUT /config/mapping` with the full mapping array

### Connection Settings Behavior

- Form pre-populates from `GET /config/settings` on page load (fetched in App.svelte init)
- "Einstellungen speichern" sends `PUT /config/settings`; on success the panel closes
- On error: inline error message below the form (no toast, no modal)

## Accessibility

- All interactive elements are keyboard-reachable (native `<button>`, `<input>`, `<select>`)
- Tally state communicated via both color and text label (never color alone)
- `aria-label` on icon-only buttons (delete row `×`)
- `aria-live="polite"` on the connection status region (header badge strip)
- `aria-live="assertive"` on the disconnect banner (loud, immediately announced)
- Minimum touch target size: 36px height (override toggles, test buttons)
- Color contrast: white text on `#dc2626` = 4.58:1 (passes AA); white on `#16a34a` = 4.54:1 (passes AA)
